# Rogue Command — plan de modding

**Recon comprobada:** 2026-10-20. Esta guía registra la instalación local y la ruta técnica; no autoriza modificar el cliente ni sustituye una prueba en partida.

- **Instalación:** `C:\Program Files (x86)\Steam\steamapps\common\Rogue Command` (Steam AppID `1461910`); `version.txt` local informa **1.0.9**. Instalación Steam presente.
- **Motor y código:** Unity **2021.3.45f2**, backend Mono, lógica administrada CIL. El proceso del juego es de 64 bits; `Assembly-CSharp.dll` es PE32/AnyCPU, algo compatible con este backend y no un indicador de que el proceso sea x86.
- **Identidad de compatibilidad verificada:** `Assembly-CSharp.dll` SHA-256 `d2da384df3318e7ac52db58eb13699ec483790b469effa46205de716825e543b`; MVID `db0e9462-128d-4296-9900-de18b4bd0c00`. REA confirmó metadatos completos para ese archivo mediante inspección estática, sin ejecutar el ensamblado. Volver a comprobar versión, hash y MVID juntos después de cualquier actualización antes de confiar en firmas o tokens.
- **Anti-cheat / modo online / política:** La ficha de Steam clasifica el juego como **un jugador**; la inspección de la carpeta local no encontró marcadores de Easy Anti-Cheat, BattlEye ni otros anti-cheat conocidos. Esto no prueba que no existan controles externos. La EULA vigente consultada exige usar únicamente el cliente sin modificar de feneq y prohíbe expresamente el uso de software cliente modificado de terceros. BepInEx/Harmony inyecta y modifica el comportamiento del cliente, por lo que **no debe considerarse una ruta segura o autorizada sin permiso escrito de feneq**. El juego sí trae un mecanismo propio `Mod/` para sobrescrituras TSV; el README instalado dice que esos archivos cambian datos de entidades existentes y no agregan entidades. Aclarar con el desarrollador si incluso el uso de ese mecanismo está cubierto por la licencia antes de distribuir modificaciones.
- **Host / compatibilidad:** Windows 10 22H2, x64/AMD64; el ejecutable local y el host son nativos, sin capa de compatibilidad. CPU reportada por Windows: AMD Ryzen Family 25 Model 80; GPU/controlador no se inspeccionaron porque no son una incertidumbre de compatibilidad para esta instalación nativa. Evidencia: inspección local del sistema y log BepInEx de la instalación, no una prueba de rendimiento.
- **Guardados, configuración y logs:** `C:\Users\Alex\AppData\LocalLow\Feneq\Rogue Command\`; existen `Profiles/`, `options.dat`, `Player.log` y `Player-prev.log`. Los perfiles contienen los `savegame.dat` descritos en el runbook. El log del loader, si está instalado, es `<instalación>\BepInEx\LogOutput.log`; configuración BepInEx bajo `BepInEx\config\`. Steam ofrece Steam Cloud; seguir el estado y las reglas de aislamiento del runbook antes de cualquier prueba y no editar sus archivos de configuración a mano.
- **Ruta comunitaria encontrada:** el formato nativo del juego es `Mod/manifest.json` + archivos `EntityBalancing` TSV listados en el manifiesto. La guía de Steam [Get Started with Modding (1.0 compatible)](https://steamcommunity.com/sharedfiles/filedetails/?id=3578664365) describe esa ruta y advierte que Excel puede producir archivos que no cargan correctamente; usar un editor de texto/TSV y conservar copias. El formato documentado permite ajustar entidades existentes, no registrar unidades nuevas. No se encontró una API oficial para contenido nuevo ni un Workshop/API de contenido en las fuentes consultadas.
- **Ruta técnica para contenido nuevo (condicionada):** si feneq autoriza por escrito el cliente modificado, la ruta que alcanza unidades/etapas/AI nuevos es **BepInEx 5 Mono x64 + Harmony**, con plugin C# que registra contenido en memoria y bundles Unity. En esta instalación ya están BepInEx **5.4.23.5** y el plugin del proyecto; el log local registra inicio del loader, hooks y carga de packs. Eso es evidencia de inicio/registro, no de que unidades, etapas o AI funcionen durante una partida. La release oficial consultada es [BepInEx 5.4.23.5](https://github.com/BepInEx/BepInEx/releases/tag/v5.4.23.5) (win-x64); su guía indica extraer al directorio del juego y colocar plugins en `BepInEx/plugins`. **No reinstalar ni volver a desplegar** sin resolver primero la restricción de EULA. Ejemplo de plugin genérico: [tutorial BepInEx 5](https://docs.bepinex.dev/v5.4.21/articles/dev_guide/plugin_tutorial/index.html); no es una API oficial específica de Rogue Command.
- **Ruta elegida para la idea del proyecto — expansión con unidades, etapas y AI originales:** técnicamente, plugin BepInEx/Harmony y contenido serializado. **Bloqueada como recomendación de uso/distribución** hasta obtener permiso de feneq, por la cláusula expresa de cliente modificado. Alternativa actualmente documentada por el juego: cambios TSV a entidades existentes, limitados a ese alcance.
- **Plan de laboratorio:** mantener las comprobaciones offline en modo de solo lectura respecto a la instalación del juego. Antes de editar datos, respaldar la carpeta completa `LocalLow\Feneq\Rogue Command\Profiles` y los archivos de configuración, conservando hashes; `um` no está instalado en este entorno, así que no afirmar que se usó `um backup`. No iniciar una partida con plugin hasta aclarar EULA. Si se autoriza una prueba posterior, seguir `docs/research/STEAM-RUNTIME-CONTROL.md` y `.agents/skills/rogue-command-steam-runtime-validation/SKILL.md`: iniciar solo desde Steam, usar un perfil QA aislado, comprobar Cloud/selector/guardados, usar ventana conocida, guardar evidencia bajo `artifacts/runtime-smoke/` y restaurar despliegues temporales por hash al cerrar.
- **Desconocidos que resolver antes de ampliar:** (1) permiso escrito de feneq para cliente BepInEx/Harmony; (2) si el formato TSV nativo tiene permiso explícito de uso/distribución bajo la EULA; (3) estado actual de Cloud y perfiles al comenzar cualquier prueba; (4) aceptación en partida de cada paso de contenido nuevo —oferta, selección, colocación, producción, renderizado, generación de etapa y decisión AI—, que no se deduce de que el loader arranque.
