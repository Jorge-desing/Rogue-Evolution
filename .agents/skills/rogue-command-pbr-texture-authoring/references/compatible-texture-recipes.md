# Compatible texture recipes

Use these recipes with the [PBR authoring contract](../SKILL.md). Compatibility means an identified image-export and validation path that preserves the production mesh and UVs. Application support alone does not establish pipeline integration. These are documented procedures, not evidence of a new bake, an ArmorPaint session, Unity import, or game rendering.

`.ptex` is the Material Maker material graph/project format: it can be saved in the application or generated by the existing template tool. The repository's integration chain is **`.ptex` → Material Maker export → four PNG maps → Blender material or Unity importer/builder**. The local Blender/Unity tools consume those images, not the `.ptex` graph directly. Regenerable templates and experiment outputs stay under `artifacts/`; a hand-authored graph needed to reproduce a promoted material is source art and must be preserved with its inputs in the task-owned source-art location, as with `content/source-art/bulwarkfoundry-material.ptex`. Do not discard such a graph merely because its filename ends in `.ptex`.

## Choose the supported path

| Technique | Authoring | Current automation | Export and acceptance |
|---|---|---|---|
| Palette, panel scale, metallic/roughness variation | Existing Material Maker 1.7 tactical graph | Existing template generator and runner; custom values are graph edits, not new CLI switches | Scalar PNGs → packer → graph/map audit → Unity checks |
| Controlled microdetail | Existing `tactical-hd-v2` detail stack | Same runner, preserving required nodes/connections | Same four-map path; frequency and visual quality require model review |
| Surface masks, markings, localized emission | Optional ArmorPaint pass after the required Material Maker baseline | Manual; no repository painting automation | Version-checked image export → packing checks → PBR/Unity review |
| Island padding and seam review | Available image-export padding on the manual path | No automatic UV seam or mip-appearance acceptance | Exported images on the unchanged UV model, then imported/compressed Unity review |

ArmorPaint is optional and is not staged in this checkout at the time of this update. Its manual currently describes version 1.1; record the actual local version and confirm the required controls and a disposable export before using that route. If unavailable, keep the Material Maker route. The runner's `three_d` workflow prepares a UV-frozen proxy and generates maps; it does not automate paint strokes or establish that a hand-painted project can be exported by the graph CLI.

## 1. Vary the finish without changing the tactical graph contract

**Inputs:** an existing supported preset, the target UV layout and agreed resolution. Prepare a fresh candidate from the repository root:

```powershell
python -m tools.Prepare-MaterialMakerTacticalTemplate --preset gunmetal_chassis --size 11 --output artifacts/texture-work/RecipeCheck/MaterialMaker/RecipeCheck.ptex
```

Keep a copy before editing. In the candidate `.ptex`, adjust only the relevant existing node parameters:

| Finish control | Existing graph location |
|---|---|
| Plate color and seam tint | `colorize_1.parameters.gradient`, `colorize_0.parameters.gradient` |
| Panel layout/scale | Existing bricks nodes inside `graph`; preserve the subgraph structure |
| Surface metallic response | `colorize_metallic.parameters.gradient` |
| Surface roughness response | `colorize_4.parameters.gradient` |

Keep gradient structure, numeric types, node names, port connections and `rogueCommandQuality.profile = "tactical-hd-v2"`. These controls describe the procedural pattern; they do not automatically identify paint, rubber, optics or exposed metal on the target model. Use the manual surface recipe when the atlas needs that distinction.

Export the edited graph with its own output directory:

```powershell
powershell -File tools/Run-MaterialMakerBake.ps1 -Workflow procedural -Preset gunmetal_chassis -TemplatePath artifacts/texture-work/RecipeCheck/MaterialMaker/RecipeCheck.ptex -OutputDirectory artifacts/texture-work/RecipeCheck/bake -SizePower 11 -Strict
```

`-TemplatePath` must already exist. Set `-Preset` to the graph's source preset: the workflow manifest records that argument, not a preset inferred from a custom graph. Record later graph edits separately. Do not use `-ForceTemplate` on an edited candidate: it regenerates the graph and replaces its edits. The runner clears its output `raw/` and matching final files; never point it at irreplaceable painting intermediates or a production texture folder. Output prefixes come from the template filename (`RecipeCheck` here), not `-UnitName`. Before deliberate promotion, give all four validated maps the exact target unit prefix together.

**Checks:** inspect the pack and quality reports, actual dimensions, metallic RGB equality, smoothness alpha and the UV-mapped model. A passing graph audit does not establish physical material separation or visual quality.

## 2. Control microdetail using the existing stack

**Input:** a candidate from recipe 1. Change one control at a time, retain a baseline and use the same export command.

- `micro_perlin.parameters.scale_x/scale_y`: adjust grain frequency; preserve their ratio for isotropic grain. Do not invent a universal scale or assume atlas frequency equals physical texel density.
- `micro_detail_blend.parameters.amount`: adjust micrograin contribution to relief; `micro_roughness_blend.parameters.amount` adjusts its roughness contribution.
- `normal_map_2.parameters.param1`: controls the resulting normal strength, including the panel relief. Keep its resolution parameter `param0` consistent with the export size.
- Retain `micro_perlin` → `micro_detail_blend` → `normal_map_2` and `micro_perlin` → `micro_roughness_blend` → `Material` roughness, along with all other required graph connections. Keep `rogueCommandQuality` values consistent with any manually changed controls; metadata alone cannot prove image content.

**Checks:** compare normal and roughness images and their appearance on the same model at close and RTS scale. Reduce detail if it obscures panel separation or becomes speckled under minification. Vector-length checks cannot detect an inverted normal convention, and a downscaled image cannot prove absence of temporal shimmer. The packer already renormalizes normals and applies albedo sharpening; additional sharpening or normal blending is not part of this recipe.

## 3. Separate surfaces with manual masks and channel controls

**Inputs:** the required Material Maker baseline and its reports, a disposable copy of the final UV mesh, and an available official ArmorPaint build whose export was checked. Keep the original baseline and the `.arm` project separately from final images.

1. Import the UV-frozen copy and the baseline maps. MetallicGloss is packed data: do not feed it to a roughness input as RGB. Use the corresponding baseline scalar metallic/roughness maps. Retain the baseline normal; this recipe adds no new normal source.
2. Use fill/paint layers with object, material or hand-painted masks supported by the local version. Assign separate masks to intact coating, exposed metal, rubber and optics. A mask must correspond to the target UV model; do not treat procedural panel edges as material IDs.
3. Enable only the channels needed for the edit. Keep intact coating and rubber dielectric; expose metal only where the material warrants it, and tune roughness to the finish. Keep masks aligned across color, metallic and roughness. Review mask edges on the model.
4. Export images into a new manual workspace using the packing recipe below. Preserve UVs, source geometry, sockets, LODs and vertex wear. Recheck exported channels even when the viewport looks correct.

**Checks:** sample corresponding UV regions in albedo, metallic and smoothness, verify masks did not leak onto another material or island, then run the PBR validation skill. Do not claim the procedural audit validates these manual masks.

## 4. Paint markings and functional emission

**Inputs:** the same optional manual workspace as recipe 3. Use paint/stamp/decal operations available in that build and bake the result into the atlas images. A painted decal here is image content, not a new runtime component.

- For identification and hazard markings, affect albedo and only the surface-response channels justified by the finish. Keep emission disabled for ordinary paint.
- For actual lamps, screens or powered paths, use a separate localized emission mask. Inspect the emission map alone and on the UV model; a bright procedural seam is not automatically a functional light.
- Retain the baseline normal and unchanged channels when no edit is needed. Verify the full exported four-map set, including unchanged maps.

**Checks and limit:** inspect placement, bleed, emission coverage and silhouette readability. The current procedural audit requires `edge_detect_emission` → `colorize_emission` → `Material`, positive `emission_energy` and the tactical profile when auditing a `.ptex`. Keep this requirement when editing that graph. If it conflicts with the requested non-emissive finish, report the incompatibility; do not add artificial glow, remove the template from provenance, or weaken checks to obtain a pass. A manual final-map review is a separate evidence layer and does not certify a changed graph.

## 5. Preserve island borders and inspect minification

**Inputs:** the unchanged UV layout and target atlas resolution. On the optional ArmorPaint path, use the texture export `Padding` control available in the local version. Choose padding for the actual island spacing and expected minification; this recipe sets no universal pixel count. The Material Maker runner exposes no padding switch.

Inspect adjacent islands, markings and emission at full resolution and reduced sizes, then inspect the imported/compressed model in Unity. Padding must not contaminate neighboring islands or alter MetallicGloss alpha. A reduced preview is a screening check; effective mip settings, compressed alpha and final seams require Unity review. If the frozen layout cannot accommodate the required borders, report the limitation and route a UV change to model authoring rather than silently changing it.

## 6. Export and pack through the existing image contract

**Automated Material Maker path:** the runner exports scalar Albedo, Metallic, Roughness, Normal and Emission, packs them, audits the graph/maps and writes reports and a workflow manifest. Inspect both reports and the process result. `-Strict` adds warning/resolution checks; the runner still enforces its quality audit without that switch.

**Optional manual path:** after confirming export support in the local ArmorPaint build, use a custom PNG preset with RGB metallic/A smoothness, or export the five scalar images with exact `<Name>_Albedo.png`, `_Metallic.png`, `_Roughness.png`, `_Normal.png`, `_Emission.png` names. For the scalar route, run from the repository root:

```powershell
python -m tools.pack_material_maker_pbr --input-dir artifacts/texture-work/RecipeCheck/manual-raw --output-dir artifacts/texture-work/RecipeCheck/manual-packed --prefix RecipeCheck --strict
```

The directories must differ. Do not run this packer on an already packed MetallicGloss set or feed smoothness to its Roughness input. It checks common dimensions, writes metallic to RGB and inverted roughness to A with the existing 0.04 roughness floor, renormalizes the normal, sharpens albedo and writes opaque RGB Albedo/Normal/Emission. Inspect the processed result. If the strict packer rejects a legitimate uniform surface, record that current limitation; do not introduce fake variation to pass.

For direct four-map export, verify channel swizzling/inversion and alpha yourself through the validation skill; that path has no new automatic acceptance command. Preserve the original Material Maker graph/reports and identify the subsequent manual edit in the handoff. Do not run the graph-generation runner over manual outputs or present its baseline report as validation of changed images.

**Unity handoff:** only the four final PNGs are promoted, with exact target names and matching dimensions. Verify Albedo/Emission sRGB, MetallicGloss linear with retained alpha, Normal import type, material bindings and unchanged mesh RGBA after the existing builder reimports. Image statistics, source-art previews and unit tests cannot establish that Unity or the game rendered the result.

## Compatibility boundaries and sources

These recipes do not integrate curvature/AO-driven automatic wear, baked triplanar projection, normals composed across tools, displacement, UDIM, changed UVs, new shader channels or neural generation. They need a separately verified export/validation path before being described as integrated.

- [Material Maker 1.7 paint panel: channels, masks, fill and stamps](https://raw.githubusercontent.com/RodZill4/material-maker/1.7/material_maker/doc/user_interface_paint_panel.rst).
- [Material Maker 1.7 export documentation](https://github.com/RodZill4/material-maker/blob/1.7/material_maker/doc/export.rst).
- [ArmorPaint official manual: layers, masking, image export, swizzling and padding](https://armorpaint.org/manual); current online manual is not a promise about an older local build.
- [Unity 2021.3 Texture Importer](https://docs.unity3d.com/2021.3/Documentation/Manual/class-TextureImporter.html).
- Repository integration authority: `tools/Prepare-MaterialMakerTacticalTemplate.py`, `tools/Run-MaterialMakerBake.ps1`, `tools/pack_material_maker_pbr.py`, `tools/audit_material_maker_output.py`, and the current Unity shader/builder. These local checks delimit the procedures above.
