# Rogue Command AssetBundle Authoring

For Level 1 prefabs, the root LODGroup must own its renderers exclusively. `VehiclePrefabBuilder` removes overlapping imported controllers while preserving independent nested groups; the canonical refresh reconciles older prefabs. Check a second Unity refresh for duplicate-owner warnings and audit actual renderer sets and transitions, not only the presence of a group.

Use this skill when preparing a unit model, native visual overlay, card Sprite, material, texture, or other non-code Unity asset for a Rogue Command content pack. For manifest or balance changes, also use `rogue-command-unit-authoring` and read the pack contract.

## Work in the authoring project

- Read `AGENTS.md`, `docs/research/AGENT-HANDOFF.md`, the AssetBundle section of `README.md`, and `unity/RogueCommandAssetAuthoring/README.md` before building. Read `content/schema/README.md` when editing pack declarations.
- Use `unity/RogueCommandAssetAuthoring/`; it is distinct from the user's `Rogue Evolution` project. Preserve its `ProjectSettings`, package manifests, Plastic/Unity Version Control metadata, Unity Cloud settings, and other authored files. Confirm `ProjectSettings/ProjectVersion.txt` before opening or building; this repository currently targets Unity 2021.3.45f2.
- Reuse the existing Editor builder and visual sample scaffolder. Keep intermediates and inspection output under ignored `artifacts/`; copy only intentional runtime assets into the pack's declared `bundles/` path.

## Choose the asset shape that the loader can use

- A native-template unit can replace one uniquely resolved renderer subtree with a script-free visual prefab while retaining the native controller and gameplay hierarchy. Keep model offsets and authored scale in the prefab's child hierarchy. This path does not retarget native animation rigs or prove that model-specific weapons and movement visuals match.
- Runtime overlay sizing measures combined world-space `MeshRenderer`/`SkinnedMeshRenderer` bounds separately: native bounds define the target (80% of native half-extent, with explicit unit/building fallbacks), and overlay bounds define the model extent; the result is one bounded uniform ratio applied to the overlay root. Exclude `_COLLIDER`, `Antenna`, or `Socket_*` anywhere in the renderer transform ancestry, not just on the renderer's own object. A visual prefab with no usable renderer extent (`<= 0.001`) is rejected with a package diagnostic rather than kept at scale 1. Derive unit-vs-building sizing from an explicit `isBuilding` flag, not from `ownerLabel` text, so diagnostic wording cannot change sizing intent. Do not add a Blender-unit `100x` heuristic or narrow scale clamp. Regression coverage checks aggregation, exclusions, fallbacks, undersized/oversized/matching scales, clamp limits, and degenerate extents; these local tests are not in-game rendering evidence.
- Render pipeline and shader self-containment: Rogue Command executes on Universal Render Pipeline (URP). Shipped native vehicles use untextured geometry rendered via `Shader Graphs/EntityColorShader`. Modded AssetBundles must embed their own compiled shaders (`RogueCommand/VehiclePBR_VertexWear` or `Standard`); never assume built-in shaders are provided by the base game assets. Setting `enableInstancing = true` on materials opts eligible renderers into instancing, but is not a guarantee of batching or reduced draw calls.
- Sockets and transforms: Search recursively for existing sockets before instantiating new GameObjects; never spawn duplicate socket transforms under the visual root when the imported FBX hierarchy already contains them, as multiple transforms matching the same role trigger `UniqueSocketRoleBinding` ambiguity and disable runtime behavior.
- Animator ownership: when a rigged source FBX contributes its own `Animator`, remove every imported Animator before `SetupAnimatorIfAvailable`; the final prefab must contain exactly one canonical Animator with a valid Generic avatar and runtime controller. Test serialized Animator counts in bundle contracts.
- Clip loopTime configuration: when deriving `shouldLoop` from a clip name, match the action token (the segment after `Action_`, or the final action name), never a substring of the unit name. A unit named `ArcLanceWalker` contains `Walk`, so `clip.name.IndexOf(\"Walk\")` incorrectly marks its `FireRecoil` and `Death` clips as looping. Compare the resolved action token (`Idle`/`Walk`/`Drive`) exactly. Also note that Unity re-imports the FBX during a scaffolder build and resets `loopTime` to the importer's defaults, so any manual `.fbx.meta` loopTime edit must be re-applied (or the scaffolder fixed) before relying on the rebuilt bundle.
- Texture importer alpha contract: `ConfigureTextureImporter` (or any equivalent importer setup) must explicitly set `alphaSource = TextureImporterAlphaSource.FromInput` and `alphaIsTransparency = false` for `*_MetallicGloss.png`. Unity's default importer may otherwise treat the alpha channel as transparency or drop it, which silently zeroes the smoothness (`A`) channel consumed by `VehiclePBR_VertexWear`. Verify the post-reimport effective state, not just `.meta` text.
- **Unified Level 1 PBR + `LODGroup` across all 18 units and 3 factories (2026-11-14):** Every active unit (including rigged `VisualOnly/Prefabs/` units `ArachnidHexapod` and `OverlordCommandHQ` via `RefreshRiggedPbrPrefabAnimator`) and all 3 factories (`BulwarkFoundry`, `ArachnidHexapodFactory`, `OverlordCommandHQFactory` via `RefreshFactoryPbrPrefab` / `BulwarkFoundryBuilder`) use unified 2048×2048 Material Maker 1.7 `RogueCommand/VehiclePBR_VertexWear` materials + `_DetailBumpMap` (`RCL_SteelMicroDetail_Normal.png`), paired `*_LODs.fbx` wired through `VehiclePrefabBuilder.SetupCompanionLodGroup` (with `RebindSkinnedLodRenderers` for rigged models), and pass `ValidatePbrVisualBundlePrefab`.
- **Companion `*_LODs.fbx` socket stripping & rigged socket deduplication:** `SetupCompanionLodGroup` instantiates `*_LODs.fbx` directly (unpacked) and destroys any duplicate empty `Socket_*`/`FirePoint_*` children inside `*LODGeometry` so `GetUniqueNamedTransform` never fails with duplicate sockets. When refreshing pre-existing rigged prefabs in `RefreshRiggedPbrPrefabAnimator`, strip stale root/external empty socket objects whose names already exist under `<Unit>Model`.
- When converting a static visual method to a rigged one (switching from `ValidateVisualBundleAssets` to `ValidateRiggedWalkerBundleAssets`), update both the prefab-creation path and the bundle-validation path; leaving the old `ValidateVisualBundleAssets` call causes "missing independent mesh parts" failures because rigged prefabs use `SkinnedMeshRenderer`, not `MeshFilter`. For `SetupCompanionLodGroup` on skinned units, configure the `*_LODs.fbx` `ModelImporter` with `animationType = Generic` and `avatarSetup = CreateFromThisModel`. Also ensure `TacticalOperationsPackScaffolder.BuildTacticalOperationsPack()` invokes `BulwarkFoundryBuilder.BuildPrefab` and bundles `BulwarkFoundryVisual.prefab`.
- Material batch-name mapping: `AssignBatchedMaterials` uses a `modelPrefix` that must match the `UNIT_NAME` passed to `batch_and_join_by_material` in the Blender build script. Source blends use varied material naming (spaces, CamelCase, underscores); `TryResolveBatchMaterial` must strip intermediate unit-name prefixes and map aliases (`armor`/`primaryarmor`, `sensor`/`sensorglass`/`sensorcyan`, `warning`/`warningorange`/`signalamber`, `arc`/`arccyan`, `wheel`/`wheelmetal`, `rubber`/`tire`) before falling back to material-key lookup. Add new aliases when a source blend introduces a naming variant not already covered. When a source blend's material has no corresponding key in the materials dictionary (e.g., Surge has `WheelHub`/`WheelRim` meshes but no `wheel` material), add fallback mappings in `TryResolveBatchMaterial` (e.g., `warning` → `magenta`, `emissive` → `arc`) or add the missing material keys to `Create{Unit}Materials`.
- A fully custom unit prefab needs the serialized game components and references required by the game. The Editor cannot author new components from the precompiled `Assembly-CSharp.dll` here; do not invent missing references or treat an incomplete prefab as installable. AssetBundles carry Unity data, not new executable `MonoBehaviour` code.
- Build for the game's Windows target with the pinned project editor. Reopen the produced bundle in Unity and verify each required asset name and type, the bundle manifest, renderer/material references, and absence of missing or `MonoBehaviour` components where a visual-only prefab is expected. Use `tools/inspect_unity_objects.py` or UnityPy as an independent serialized-object inventory when useful.

## Report evidence accurately

An Editor build and successful AssetBundle import are local authoring evidence. They do not prove that Rogue Command resolves the asset, registers the unit, or renders it in a match. For those claims, use `rogue-command-steam-runtime-validation` and record the in-game observation separately. Do not replace a failed or missing asset with a placeholder bundle and call the pack complete.

## Canonical Two-Level Module Bundles

- The module manifest's `preset` field identifies only its Material Maker PBR set. Reusable geometry uses independent `geometryPreset` and optional `geometryLayout` fields from `content/source-art/canonical-visual-module-roles.json` (schema 2). The registry must cover the complete factory catalog and each binding carries slot, geometry role, allowed visual roles, optional variant restrictions, and exact `variantRoles` assignments. Python validates the bindings against all factory metadata and dispatches the selected factory; Unity reads the same bindings, layouts, and variant assignments, then requires one schema-3 manifest entry per unique `(variantId, slotId)` with the exact role, preset, and layout plus the matching registry SHA-256. Do not add a third preset allowlist in C# or silently accept an assigned recipe that the Blender builder does not invoke.
- Every active Level 2 module row has an explicit reusable geometry preset. The pack declarations bind 57 modules across 35 variants and use all 47 registered recipes. `content/source-art/canonical-visual-modules.json` uses schema 3, pins the registry and build-policy hashes, and has one row per exact `(variantId, slotId)` assignment. The global user-authorized no-calibration-limits policy applies to all geometry builders; outputs must say `UNCALIBRATED_USER_AUTHORIZED` and are not performance evidence. See the latest handoff for the current complete build, validation, and bundle hashes. Bind the Bulwark Battleship Tungsten row to `geometryPreset: era_brick_cassette_v1` and `geometryLayout: bulwark_side_skirt_array_v2`; it produces ten Level 2 side cassettes, five per side, while the six Level 1 front cassettes remain intact. The coaxial connector is variant-restricted in the shared registry to `tactical-operations:gravitas-breaker-quantum-hyperdrive-alloy` at `Sponsons`.
- Reconcile AssetBundle labels for canonical module prefabs against the active manifest before building. Clear the current pack labels only from unreferenced `RCLModule_*.prefab` files in the shared module prefab folder; preserve the files and unrelated bundle labels. This keeps stale module containers out of rebuilt packs without deleting prior authoring assets.
- Validate fit-sensitive modules against the exact current Level 1 FBX imported by their Unity prefab. A newer source `.blend` may show a wider or moved host surface; do not accept its integrated render as evidence for an older FBX. The refreshed Bulwark Level 1 FBX has side support planes at `x=±1.312 m`; its current Level 2 ERA array seats ten backing plates, five per side. The integration check measures every backing plate against the host, checks belt clearance/overlap, and confirms the six existing front plates remain separate Level 1 geometry. Calibration no longer gates Level 1 or Level 2 builds; distinguish authoring validation from runtime evidence.
- For close Level 2 inspection, use `tools/Render-CanonicalVisualModuleCloseViews.py` with Blender 4.5.14 and the default 0.95 frame fill to render front, reverse, isometric, and top unit-scale views. Review side-mounted armor face-on and also mount it to the current host FBX at unit scale; isolated normalized views diagnose module geometry but cannot establish fit.
- For arrays with declared cassette positions, pass `--detail-clusters` to render four close crops at every position. Review both sides on the current host FBX, retain the resulting views with the build evidence, and compare contact/clearance measurements against the same host revision.
- Keep geometry presets geometry-only and deterministic in Blender. An optional Hardflow pilot may create the reviewed shape, but the canonical generator replays the recipe with Blender built-ins; it must not depend on the extension. Do not modify or falsely calibrate `model-budget-profile.json` to enable the scoped build-policy exception.
- Module prefabs are visual-only `GameObject`s: no `MonoBehaviour`, collider, joint, or gameplay component. The runtime accepts only `ERA`, `APS`, `Sponsons`, and `FuelDrums`, mounted beneath `RCL_AttachmentGroup_<Slot>` at the corresponding existing `Socket_Hardpoint_<Slot>`.
- The canonical Unity module builder compares the generated module manifest to each pack variant and loads the owning Level 1 prefab hierarchy. It rejects missing, duplicate, or noncanonical hardpoint sockets for slots used by Level 2 modules before labeling or building bundles.
- The full canonical build (`CanonicalVisualModuleBuilder.RefreshAndBuildCanonicalModules` inside `Build-CanonicalVisualModules.ps1`) refreshes and validates all 18 active unit prefabs and 3 factory prefabs (`RogueCommandVisualSampleScaffolder.RefreshCanonicalLevelOneVisualsCore`), saves/refreshes the `AssetDatabase`, and builds Level 2 modules/bundles (`BuildCanonicalModulesCore`) in a single Unity `2021.3.45f2` batchmode session (`Validated ... unit prefabs...` and `Built ... visual-only modules...`). The scaffold retains authored FBX hardpoints and only synthesizes a missing canonical anchor as a compatibility fallback; the post-refresh gate requires four distinct `Socket_Hardpoint_{ERA,APS,Sponsons,FuelDrums}` on every active unit prefab and enforces `Socket_Hardpoint_ERA == (0,0,0)` on `BulwarkSiegeTank`.
- A module reference uses the owning unit's `assetBundleId` and the exact AssetBundle container key in `assetName`; there is no per-module bundle ID. This project's Unity builder emits lowercase container keys, so keep the generated manifest asset names aligned with the serialized keys and verify by reopening the bundle.
- `CanonicalVisualModuleBuilder` labels the module prefabs and every asset referenced by selected pack `content.json` files before `RogueCommandAssetBundleBuilder.BuildContentPacksByName`. If a pack adds a reference to an existing unlabeled prefab/card, label it for the declared bundle before building; otherwise the bundle reference audit will fail.
- Run `tools/Build-CanonicalVisualModules.ps1` for the fail-closed 10-phase two-level pipeline in exact order:
  1) `level1-models` (`-RebuildLevelOneModels`; rebuilds v2 source `.blend`s for selected packs and runs `test_sample_native_v2_surface_fit.py` for `sample-native-expansion`), 2) `level1-textures` (`-RebuildLevelOneTextures`), 3) `blender` (pinned Blender 4.5.14 Level 2 FBXs), 4) `textures` (Material Maker 1.7 four-map bakes with `-TextureSizePower` `9..12`, default `11` = `2048`, `-MaxParallelExports` `1..8`, `-PackWorkers` `1..8`), 5) `unity` (single-startup Unity 2021.3.45f2 `RefreshAndBuildCanonicalModules`), 6) `unity-audit` (`tools.audit_unity_build --strict`), 7) `staging-and-pack-validation` (pack/reference audits plus automatic `tools/validate_native_visual_roots.py <stagedRoot> --game-root $GameRoot` when `$GameRoot\version.txt` exists for packs declaring `visualRootPath`/`nativeRigRetarget` unless `-SkipNativeVisualValidation`, plus `New-CanonicalVisualBuildManifest`/`Assert-CanonicalVisualBuildFreshness`), 8) `animation-matrix` (`tools.run_animation_validation_matrix --strict-loops`, gating promotion unless `-SkipAnimationMatrix`), 9) `bundle-promotion` (`Invoke-CanonicalBundlePromotion` with SHA-256 backup in `<ArtifactRoot>/prior-bundles-backup/`, opt out via `-NoPromoteBundles`), and 10) `package-loader` (`-PackageLoader` invoking `tools/Package-Loader.ps1 -CanonicalVisualArtifactRoot <ArtifactRoot> -GameRoot $GameRoot`).
  - Both texture phases run one batch audit via `tools.audit_material_maker_output --directory <dir> --prefixes <list...> --workflow urp --output-dir <ArtifactRoot>/logs --output <batchJson>` (emitting per-prefix `mm-audit-<prefix>.json`, `materialMakerBatchQualityReport`, and exit code `2` on failure while retaining `--prefix` single mode).
  - Supports full `-Incremental` caching (`artifacts/canonical-level2-cache.json` via `CanonicalVisualBuildProvenance.ps1` across `level1-models`, `level1-textures`, `blender`, `textures`, and `unity` artifact hydration with SHA-256 verification and upstream invalidation), `-SkipBlender`/`-SkipTextures`/`-SkipLevelOneRefresh`/`-SkipUnityBuild`, `-DryRun`, `-Packs`, `-GameRoot`, and `-ArtifactRoot`; writes `<ArtifactRoot>/build-summary.json` in `try/finally` (except on `-DryRun`).
  - Fail-closed rollback: if `bundle-promotion` or `package-loader` errors after promotion starts, `catch` automatically invokes `Restore-CanonicalBundlePromotion` for backed-up packs and records `rollback` in `build-summary.json`. Standalone `Build-CanonicalVisualModules.ps1 -RestoreBundlesFrom <backupRoot> [-Packs ...] [-DryRun]` calls `Restore-CanonicalBundlePromotion` directly (restoring `existed=true` bundles and deleting `existed=false` bundles with SHA-256 verification). Each build writes to `artifacts/canonical-level2-<UTC>/` and `tools/Package-Loader.ps1` verifies its source fingerprint and staged hashes (or accepts `-CanonicalVisualArtifactRoot`).
- Reopen both built packs and verify every module key, shader/material dependency, and script-free prefab. A successful Editor build remains local authoring evidence only.
- For an independent serialized component audit, use `UnityPy.load(bundle)` and inspect each `GameObject.m_Component` for GameObject names containing `RCLModule_`; allow only `Transform`, `MeshFilter`, and `MeshRenderer`. The name filter can match batch and geometry children, so report GameObject/component counts rather than prefab counts. This is static bundle evidence, not runtime proof.

## Bulwark foundry

`TacticalOperationsPackScaffolder.BuildBulwarkFoundry` uses the global no-calibration-limits authoring policy, imports its PBR maps and RGBA mesh attributes, creates a script-free three-LOD prefab, and rebuilds the tactical bundle under `artifacts/bulwark-foundry-build/bundles/`. It reopens both bundles and rejects removal of any prior asset address. Check `content/source-art/bulwarkfoundry-build-report.json` for hashes and `UNCALIBRATED_USER_AUTHORIZED` status. Native factory scale, registration, and appearance require separate in-game evidence.

Before rebuilding the sample-native bundle, ensure ArachnidHexapod.fbx is the animated armature export from arachnidhexapod-rigged.blend. A static export at the same path produces an invalid Generic Avatar and omits action clips. Preserve the source blend and back up the replaced FBX.

## PowerShell host module resolution

`CanonicalVisualBuildProvenance.ps1` imports `Microsoft.PowerShell.Utility` from `$PSHOME/Modules` so Windows PowerShell 5.1 does not load a PowerShell 7 module inherited through `PSModulePath`. This provides the host's `Get-FileHash` for cache and bundle provenance.
