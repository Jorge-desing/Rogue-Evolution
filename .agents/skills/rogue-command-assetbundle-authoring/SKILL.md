# Rogue Command AssetBundle Authoring

Use this skill when preparing a unit model, native visual overlay, card Sprite, material, texture, or other non-code Unity asset for a Rogue Command content pack. For manifest or balance changes, also use `rogue-command-unit-authoring` and read the pack contract.

## Work in the authoring project

- Read `AGENTS.md`, `docs/research/AGENT-HANDOFF.md`, the AssetBundle section of `README.md`, and `unity/RogueCommandAssetAuthoring/README.md` before building. Read `content/schema/README.md` when editing pack declarations.
- Use `unity/RogueCommandAssetAuthoring/`; it is distinct from the user's `Rogue Evolution` project. Preserve its `ProjectSettings`, package manifests, Plastic/Unity Version Control metadata, Unity Cloud settings, and other authored files. Confirm `ProjectSettings/ProjectVersion.txt` before opening or building; this repository currently targets Unity 2021.3.45f2.
- Reuse the existing Editor builder and visual sample scaffolder. Keep intermediates and inspection output under ignored `artifacts/`; copy only intentional runtime assets into the pack's declared `bundles/` path.

## Choose the asset shape that the loader can use

- A native-template unit can replace one uniquely resolved renderer subtree with a script-free visual prefab while retaining the native controller and gameplay hierarchy. Keep model offsets and authored scale in the prefab's child hierarchy. This path does not retarget native animation rigs or prove that model-specific weapons and movement visuals match.
- Runtime overlay sizing measures combined world-space `MeshRenderer`/`SkinnedMeshRenderer` bounds separately: native bounds define the target (80% of native half-extent, with explicit unit/building fallbacks), and overlay bounds define the model extent; the result is one bounded uniform ratio applied to the overlay root. Exclude `_COLLIDER`, `Antenna`, or `Socket_*` anywhere in the renderer transform ancestry, not just on the renderer's own object. A visual prefab with no usable renderer extent (`<= 0.001`) is rejected with a package diagnostic rather than kept at scale 1. Derive unit-vs-building sizing from an explicit `isBuilding` flag, not from `ownerLabel` text, so diagnostic wording cannot change sizing intent. Do not add a Blender-unit `100x` heuristic or narrow scale clamp. Regression coverage checks aggregation, exclusions, fallbacks, undersized/oversized/matching scales, clamp limits, and degenerate extents; these local tests are not in-game rendering evidence.
- Render pipeline and shader self-containment: Rogue Command executes on Universal Render Pipeline (URP). Shipped native vehicles use untextured geometry rendered via `Shader Graphs/EntityColorShader`. Modded AssetBundles must embed their own compiled shaders (`RogueCommand/VehiclePBR_VertexWear` or `Standard`); never assume built-in shaders are provided by the base game assets. Setting `enableInstancing = true` on materials opts eligible renderers into instancing, but is not a guarantee of batching or reduced draw calls.
- Sockets and transforms: Search recursively for existing sockets before instantiating new GameObjects; never spawn duplicate socket transforms under the visual root when the imported FBX hierarchy already contains them, as multiple transforms matching the same role trigger `UniqueSocketRoleBinding` ambiguity and disable runtime behavior.
- Animator ownership: when a rigged source FBX contributes its own `Animator`, remove every imported Animator before `SetupAnimatorIfAvailable`; the final prefab must contain exactly one canonical Animator with a valid Generic avatar and runtime controller. Test serialized Animator counts in bundle contracts.
- Clip loopTime configuration: when deriving `shouldLoop` from a clip name, match the action token (the segment after `Action_`, or the final action name), never a substring of the unit name. A unit named `ArcLanceWalker` contains `Walk`, so `clip.name.IndexOf(\"Walk\")` incorrectly marks its `FireRecoil` and `Death` clips as looping. Compare the resolved action token (`Idle`/`Walk`/`Drive`) exactly. Also note that Unity re-imports the FBX during a scaffolder build and resets `loopTime` to the importer's defaults, so any manual `.fbx.meta` loopTime edit must be re-applied (or the scaffolder fixed) before relying on the rebuilt bundle.
- Texture importer alpha contract: `ConfigureTextureImporter` (or any equivalent importer setup) must explicitly set `alphaSource = TextureImporterAlphaSource.FromInput` and `alphaIsTransparency = false` for `*_MetallicGloss.png`. Unity's default importer may otherwise treat the alpha channel as transparency or drop it, which silently zeroes the smoothness (`A`) channel consumed by `VehiclePBR_VertexWear`. Verify the post-reimport effective state, not just `.meta` text.
- **VisualOnly/Prefabs can use `CreateRiggedPbrVisual`.** Units in `VisualOnly/Prefabs/` (ArachnidHexapod, OverlordCommandHQ) are now created by `CreateRiggedPbrVisual`, which instantiates the rigged FBX, adds canonical sockets, configures Animator with Generic Avatar and controller, and saves as prefab. These units use the batch material system (not PBR textures) and do not have card sprites; pass `null, null` for card suffix/name in `ValidateRiggedWalkerBundleAssets`. Their AnimatorControllers must still be added to the bundle asset list and validation path.
- **PBR validation must be skipped for rigged models.** `ValidatePbrVisualBundlePrefab` checks for `RogueCommand/VehiclePBR_VertexWear` shader and vertex-wear settings. Rigged models (ArachnidHexapod, OverlordCommandHQ) use the batch material system, not PBR textures, so their materials do not use `VehiclePBR_VertexWear`. Comment out or guard the `ValidatePbrVisualBundlePrefab` calls for these units when converting from static to rigged visuals; otherwise the bundle build fails with "material is missing RogueCommand/VehiclePBR_VertexWear or the expected vertex-wear setting."
- When converting a static visual method to a rigged one (switching from `ValidateVisualBundleAssets` to `ValidateRiggedWalkerBundleAssets`), update both the prefab-creation path and the bundle-validation path; leaving the old `ValidateVisualBundleAssets` call causes \"missing independent mesh parts\" failures because rigged prefabs use `SkinnedMeshRenderer`, not `MeshFilter`. Also add `ValidateWalkerModelSource` calls for the new units in `ValidateRiggedWalkerSources` so the ModelImporter is configured (`Generic` animation type, `Create From This Model` avatar, `importAnimation = true`, `optimizeGameObjects = false`) before prefab generation.
- Material batch-name mapping: `AssignBatchedMaterials` uses a `modelPrefix` that must match the `UNIT_NAME` passed to `batch_and_join_by_material` in the Blender build script. Source blends use varied material naming (spaces, CamelCase, underscores); `TryResolveBatchMaterial` must strip intermediate unit-name prefixes and map aliases (`armor`/`primaryarmor`, `sensor`/`sensorglass`/`sensorcyan`, `warning`/`warningorange`/`signalamber`, `arc`/`arccyan`, `wheel`/`wheelmetal`, `rubber`/`tire`) before falling back to material-key lookup. Add new aliases when a source blend introduces a naming variant not already covered. When a source blend's material has no corresponding key in the materials dictionary (e.g., Surge has `WheelHub`/`WheelRim` meshes but no `wheel` material), add fallback mappings in `TryResolveBatchMaterial` (e.g., `warning` → `magenta`, `emissive` → `arc`) or add the missing material keys to `Create{Unit}Materials`.
- A fully custom unit prefab needs the serialized game components and references required by the game. The Editor cannot author new components from the precompiled `Assembly-CSharp.dll` here; do not invent missing references or treat an incomplete prefab as installable. AssetBundles carry Unity data, not new executable `MonoBehaviour` code.
- Build for the game's Windows target with the pinned project editor. Reopen the produced bundle in Unity and verify each required asset name and type, the bundle manifest, renderer/material references, and absence of missing or `MonoBehaviour` components where a visual-only prefab is expected. Use `tools/inspect_unity_objects.py` or UnityPy as an independent serialized-object inventory when useful.

## Report evidence accurately

An Editor build and successful AssetBundle import are local authoring evidence. They do not prove that Rogue Command resolves the asset, registers the unit, or renders it in a match. For those claims, use `rogue-command-steam-runtime-validation` and record the in-game observation separately. Do not replace a failed or missing asset with a placeholder bundle and call the pack complete.

## Canonical Two-Level Module Bundles

- Module prefabs are visual-only `GameObject`s: no `MonoBehaviour`, collider, joint, or gameplay component. The runtime accepts only `ERA`, `APS`, `Sponsons`, and `FuelDrums`, mounted beneath `RCL_AttachmentGroup_<Slot>` at the corresponding existing `Socket_Hardpoint_<Slot>`.
- The canonical Unity module builder compares the generated module manifest to each pack variant and loads the owning Level 1 prefab hierarchy. It rejects missing, duplicate, or noncanonical hardpoint sockets for slots used by Level 2 modules before labeling or building bundles.
- The full canonical build refreshes Sandlance Scout, Skirmish Strike Bike, Colossus Siege Platform, and Surge Arc Tank Level 1 prefabs before the Level 2 binding audit. The scaffold retains authored FBX hardpoints and only synthesizes a missing canonical anchor as a compatibility fallback; the post-refresh gate requires one each of ERA, APS, Sponsons, and FuelDrums on those four prefabs.
- A module reference uses the owning unit's `assetBundleId` and the exact AssetBundle container key in `assetName`; there is no per-module bundle ID. This project's Unity builder emits lowercase container keys, so keep the generated manifest asset names aligned with the serialized keys and verify by reopening the bundle.
- `CanonicalVisualModuleBuilder` labels the module prefabs and every asset referenced by selected pack `content.json` files before `RogueCommandAssetBundleBuilder.BuildContentPacksByName`. If a pack adds a reference to an existing unlabeled prefab/card, label it for the declared bundle before building; otherwise the bundle reference audit will fail.
- Run `tools/Build-CanonicalVisualModules.ps1` for the complete two-level pipeline: pinned Blender 4.5.14 Level 2 FBX generation, strict Material Maker 1.7 four-map bakes, Unity 2021.3.45f2 Level 1 prefab refresh and Level 2 module/bundle build, staging, and pack/reference validation. It writes `artifacts/canonical-two-level/build-manifest.json` with a fingerprint of the generation inputs and SHA-256 hashes for staged content and bundles. The versioned bundle files under `content/packs/*/bundles/` are snapshots and may be stale after asset or manifest edits; `tools/Package-Loader.ps1` verifies the source fingerprint and staged hashes before packaging the fresh sample-native build.
- Reopen both built packs and verify every module key, shader/material dependency, and script-free prefab. A successful Editor build remains local authoring evidence only.
