# Native UI and intermission workflow

For multi-step UI flows, read [Automation](automation.md). Wait on `diagnostics_get_runtime_control_surface` fields or use `diagnostics_wait_for_ui_text` for a unique interactable control. A successful wait is an observation; refresh native targets and let the action validate them. An uncertain effect requires a fresh read before deciding whether another mutation is appropriate.

Use this reference for screenshot-free control discovery and the run director between combat stages. It does not cover the combat AI Director.

`diagnostics_ui_set_value` targets an exact current census `hierarchyPath` and `gameObjectId`. Its `kind` selects slider (number), toggle/switch (boolean), dropdown (integer index), or TMP text (string); `submit=true` dispatches TMP end-edit. Inspect `nativeCallInvoked` and `effectObserved` separately. Use only for an authorized UI change; local simulated validation does not prove in-game operation. A switch already at the requested value reports the observed state without invoking its event again.

Local verification uses `dotnet run --project tests/UiValueDirector/UiValueDirector.csproj -c Release`: it compiles the real value director with simulated controls and checks dispatch, stale/disabled/ambiguous targets, native event invocation and TMP validation rejection. This harness does not establish Unity or in-game behavior.

The value payload uses Base64-encoded UTF-8 JSON internally because the installed generic bridge splits arguments on commas and strips quotes. Keep this encoding in the MCP handler; callers still supply ordinary typed `value` fields. After restarting the game, re-resolve LoaderDiagnostics IDs; an existing MCP process can retain an obsolete ID.

## Discover and operate native UI

1. Start with `diagnostics_get_runtime_control_surface` for the active scene, frame number, and accessible UI census in one Unity-thread call. It also returns bounded native Shop/RemoveCardView state; an active `Intermission` scene adds run progression, the node census and graph/routes, reward/deck state, and navigator state. On other scenes the intermission section is marked as excluded. Use `diagnostics_get_ui_accessibility_census` with a label query when you need a narrower or refreshed control list; both reads are screenshot-free.
   Unity UI sliders report `value`, `minValue`, `maxValue` and `wholeNumbers`; toggles report `value`; Unity UI dropdowns report their selected index, bounded option labels and `omittedOptionCount`. Michsky switches/dropdowns also report values; dropdowns include bounded options. TMP inputs report text, readOnly and characterLimit. valueControlType identifies the native value component when components share a GameObject. Read a fresh census before acting.
2. If a screen is changing, use `diagnostics_wait_for_ui_text` with the exact label or current hierarchy path and a bounded timeout. Re-run the census after every scene or panel transition; Unity instance IDs and paths can become stale.
3. For a Unity `Selectable` or a canvas-backed native `IPointerClickHandler`, use `diagnostics_ui_click_text` with a unique exact label or the exact scene-qualified census path. This uses the native EventSystem click path and fails closed for ambiguous, occluded, inactive, or non-interactable targets.
4. For a non-Selectable `Michsky.UI.Reach.ButtonManager`, use `diagnostics_ui_invoke_native_button` with the current scene, exact object selector, expected button text, and hierarchy path when needed to disambiguate. Before invoking a control that opens a dialog or advances a flow, inspect its listener target and method; do not invoke arbitrary callbacks through generic reflection.
5. Read the resulting scene/UI/run state and verify the requested postcondition. After a timeout, query that postcondition before retrying an in-flight action.

Prefer purpose-built actions over UI clicks for gameplay controls. Use the UI endpoints for native menus and controls that have no dedicated typed action. If an unlabeled control is needed, resolve its exact path; do not guess coordinates or switch to screenshots/Computer Use.

## Intermission and run director

- Prefer `diagnostics_get_runtime_control_surface` for a same-thread intermission/UI baseline. Its UI result is bounded by `maxUiResults` (1-100) and includes the native pointer controls exposed by the accessibility census; intermission node/route, reward/deck, and navigator sections are independently reported, so one section error does not erase the others. `diagnostics_fast_snapshot` preset `intermission` remains available for a broader best-effort view whose component reads may span Unity frames.
- Use `diagnostics_get_intermission_census` to obtain the current node's integer `level`/`field` keys and `choosable` status. Use `diagnostics_get_intermission_graph` to inspect routes and `diagnostics_get_intermission_node` for one node's rewards and edges. Do not infer choosability from a map graphic or localized preview name.
- `diagnostics_order_select_level_node` changes map selection only and does not load a level. `diagnostics_order_enter_level` classifies the selected node using native LevelMap reward predicates before loading. Reward nodes use `LoadScene.LoadLevel()` only and never fall through to `LoadNextLevel`; only classified combat nodes may start that corridor; unknown classifications fail closed. Reward success means the node was selected and its reward postcondition was observed (`entered=false`), not that combat began. This action changes the active run; use it only when the request authorizes continuing that run. Do not use synthetic stage jumps as normal navigation.
- Before choosing, skipping, rerolling, or assigning a reward, read `diagnostics_get_intermission_reward_state` and confirm the active queue, offered slot/ID, and intended effect. Use `diagnostics_order_choose_intermission_reward`, `diagnostics_order_skip_intermission_reward`, `diagnostics_order_reroll_intermission_reward`, or `diagnostics_order_assign_intermission_upgrade` as appropriate, then read the reward state and UI again. Treat reward and deck changes as run mutations; do not choose or skip on the user's behalf without the request specifying that choice.
- For Shop and card-removal controls, first read `diagnostics_get_intermission_native_panel_state`. Buy a current offer by its scene-local `offerId`, use the native shop-reroll action only when `canReroll=true`, and remove only a unique current `removalCards[].entityId` after `isRemoveCardClickReady=true`. Use the dedicated cancel action to close an active removal panel. These actions call native methods and do not bypass the removal delay. If a result reports `nativeCallInvoked=true` and `effectObserved=false`, refresh both the panel state and UI before any further mutation; do not retry blindly.
- After a level transition, inspect `LoadingHider` and the native `Iniciar` control with the accessibility census. Click its exact scene-qualified path through `diagnostics_ui_click_text`, then verify the gameplay state. A `Game` scene or `Time.timeScale=1` by itself does not prove gameplay has started.
- If the native director cannot enter the requested node, or a transition stalls, stop at that boundary and report the observed state. Follow `docs/research/STEAM-RUNTIME-CONTROL.md` for any documented exceptional transition procedure; do not advance a saved route just to force a different stage/profile.

Preserve the existing profile, save, and tutorial state. Any new-run QA must follow the cloned-profile procedure in `rogue-command-steam-runtime-validation` and the runtime runbook.

## Wait for reward and deck postconditions

Use `automation_wait_for_state` with `tool=diagnostics_get_intermission_reward_state` and bounded `arguments.maxCards` after an authorized reward action. Read the current reward report first and use its actual field paths and typed values in `expect`; field names in illustrative fixtures are not runtime contracts. Set `stableSamples=2` for asynchronous panel/queue transitions. The result retains only the latest report and matching streak.

Verify the intended offered ID, queue transition or deck change rather than merely waiting for an Intermission scene. A failed query stops the wait; a missing field remains pending until timeout. Do not treat a missing/truncated card row as proof that an item was consumed. If the action was invoked with an unobserved effect, inspect fresh reward and native-panel state before deciding on any additional mutation. Waiting never chooses, skips, rerolls, buys or advances the route.

## Guarded reward choices and Shop purchases

`diagnostics_order_choose_intermission_reward` and `diagnostics_order_buy_intermission_shop_offer` accept optional `preconditions` and `dryRun`. Preconditions map 1–8 JSON Pointer paths in the respective fresh reward/native-panel report to exact typed expected values, for example `{"/canReroll":true}` for a Shop state guard. Read the current report to select meaningful paths. Invalid pointers, missing fields, mismatches and query/queried-section errors prevent the action.

`dryRun=true` queries state and returns checks and the observation with `nativeCallInvoked=false`; it does not validate native affordability, click readiness, target identity or authorization. `actionValidationRequired=true` makes that boundary explicit. With no preconditions, a dry run only confirms that the census was read successfully. Dry runs never reserve an offer. A guarded live action performs one fresh read and then calls the existing native action once; this is not atomic across the two Unity calls. Native target checks remain authoritative, and uncertain results require inspection before any retry. Both new controls are optional; existing calls retain their behavior.

A failed guarded action or dry-run preflight stops its sequence even when `stopOnFailure=false`. Inspect the returned checks before any further mutation.

## Native Shop exit

The loader now provides `OrderLeaveIntermissionShopJson(gameObjectId)` backed by `ShopLeaveButton.OnPress()`. It requires an active Shop without removal dialog, an exact active leave component ID and an interactable UI control. The native method finishes the node, writes the save and requests intermission. MCP exposes `diagnostics_order_leave_intermission_shop` with required integer `gameObjectId`; use the current leave-control GameObject ID. Bridge and simulated native branch checks pass. In-game transition remains unverified. An invoked but unobserved transition requires a fresh read before any retry.

Shop exit validation now also rejects disabled Behaviour UI controls; simulated native regression covers a closed shop, stale IDs, non-interactable controls, unobserved transition, native exception and observed closure. These are local simulated checks, not in-game transition evidence.

When validating the native action, build the validation harness to an explicit ignored output directory and execute that exact DLL. A `dotnet run --artifacts-path` invocation here selected the previous executable; an old test count cannot establish current-source acceptance. Shop leave-target discovery uses Resources.FindObjectsOfTypeAll with active and loaded-scene gates to exclude prefab assets.
